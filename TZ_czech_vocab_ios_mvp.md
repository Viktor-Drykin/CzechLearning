**Версия:** 1.0
**Дата:** 2026-09-20
**Назначение документа:** спецификация для разработки через Claude Code.

---

## 1. Обзор

### 1.1. Продукт

Мобильное приложение для iOS, помогающее русско- и украиноязычным пользователям заучивать чешскую лексику уровней A1–B1 методом карточек с интервальным повторением.

### 1.2. Целевая аудитория

Взрослые носители русского и украинского языков, живущие в Чехии или готовящиеся к переезду. Уровень владения чешским — от нуля до B1.

### 1.3. Границы MVP

**Входит в объём:**

- импорт готового словаря из CSV в локальную БД;
- колоды по уровням (A1/A2/B1) и темам (57 категорий);
- пять режимов тренировки;
- алгоритм интервального повторения (SM-2);
- озвучка чешских слов и примеров через системный TTS;
- картинки к словам с дисковым кэшем;
- экран прогресса;
- переключение языка подсказок: русский / украинский.

**Не входит в объём MVP** (не реализовывать, но не закрывать архитектурно):

- аккаунты, бэкенд, синхронизация между устройствами;
- монетизация, подписки, пейволл;
- геймификация (стрики, достижения), push-уведомления;
- распознавание речи и оценка произношения;
- пользовательские колоды и добавление своих слов;
- грамматические упражнения (род, вид, падежи) — данные для них есть, но режимы делаются после MVP.

### 1.4. Ключевой принцип

Приложение полностью работает офлайн. Сеть нужна только для загрузки картинок; без сети приложение функционирует без деградации логики обучения.

## 4. Модель данных

### 4.1. Перечисления

```swift
enum PartOfSpeech: String, Codable, CaseIterable {
    case noun          // сущ.
    case verb          // гл.
    case adjective     // прил.
    case adverb        // нареч.
    case numeral       // числ.
    case pronoun       // мест.
    case preposition   // предл.
    case conjunction   // союз
    case particle      // частица
    case interjection  // межд.
    case phrase        // фраза

    init?(csvValue: String)   // маппинг с русских сокращений
}

enum GrammarTag: String, Codable {
    case masculineAnimate      // м.р. одуш.
    case masculineInanimate    // м.р. неодуш.
    case feminine, neuter, plural   // ж.р. ср.р. мн.ч.
    case imperfective, perfective              // несов. сов.
}

enum CEFRLevel: String, Codable, CaseIterable, Comparable {
    case a1 = "A1", a2 = "A2", b1 = "B1"
}

enum TranslationLanguage: String, Codable, CaseIterable {
    case russian, ukrainian
}

enum CardState: Int, Codable {
    case new = 0, learning = 1, review = 2, relearning = 3
}

enum ReviewGrade: Int, Codable {
    case again = 0, hard = 1, good = 2, easy = 3
}

enum StudyMode: String, Codable, CaseIterable {
    case flashcards, multipleChoice, typing, listening, matching
}
```

## 5. Импорт данных

### 5.1. Когда выполняется

При первом запуске приложения и при изменении версии данных. Версия данных хранится в `UserDefaults` под ключом `dataVersion` (начальное значение `1`). Если константа в коде больше сохранённой — выполняется переимпорт.

### 5.2. Алгоритм

1. Прочитать CSV из бандла, отбросить BOM.
2. Распарсить по RFC 4180 (собственный парсер, учитывающий кавычки и запятые внутри полей).
3. Для каждой строки провалидировать: `id` — число, `level` и `part_of_speech` — из допустимых значений, `czech`/`russian`/`ukrainian`/примеры — непустые. Невалидная строка → залогировать и пропустить, импорт не прерывать.
4. Построить `searchKey`: `czech` → NFD-нормализация → удалить диакритику (категория `Mn`) → lowercase.
5. Вставить `Word`. Для существующих `id` — обновить поля, **не трогая связанный `WordProgress`** (это делает переимпорт безопасным для прогресса пользователя).
6. `WordProgress` при первом импорте **не создавать**: он создаётся лениво при первом показе карточки.

### 5.3. Требования

- Импорт 1744 строк должен укладываться в 3 секунды на iPhone 12.
- Импорт выполняется в фоновом контексте, UI показывает индикатор прогресса.
- Импорт идемпотентен: повторный запуск не создаёт дубликатов.

## 6. Алгоритм интервального повторения

Модифицированный SM-2. Реализуется как чистая функция без зависимостей от SwiftData — чтобы её можно было покрыть тестами.

```swift
struct SRSScheduler {
    static func schedule(
        progress: SRSState,
        grade: ReviewGrade,
        now: Date
    ) -> SRSState
}
```

### 6.1. Константы

```swift
let initialEase = 2.5
let minimumEase = 1.3
let learningSteps: [TimeInterval] = [60, 600]        // 1 мин, 10 мин
let relearningSteps: [TimeInterval] = [600]          // 10 мин
let graduatingIntervalDays = 1.0
let easyIntervalDays = 4.0
let lapseIntervalMultiplier = 0.5
let minimumReviewIntervalDays = 1.0
let maximumIntervalDays = 365.0
let intervalFuzzPercent = 0.05                       // ±5% разброс
```

### 6.2. Переходы состояний

**`new` → первый ответ:**

| Оценка | Результат |
|---|---|
| `again` | `learning`, шаг 0, due = now + 60 с |
| `hard` | `learning`, шаг 0, due = now + 60 с |
| `good` | `learning`, шаг 1, due = now + 600 с |
| `easy` | `review`, интервал = 4 дня |

**`learning`:**

| Оценка | Результат |
|---|---|
| `again` | шаг сбрасывается в 0, due = now + 60 с |
| `hard` | шаг не меняется, due = now + текущий шаг |
| `good` | шаг +1. Если шаг вышел за границы массива → `review`, интервал = 1 день, ease = 2.5 |
| `easy` | → `review`, интервал = 4 дня |

**`review`:**

Сначала корректируется ease:

| Оценка | Δ ease |
|---|---|
| `again` | −0.20 |
| `hard` | −0.15 |
| `good` | 0 |
| `easy` | +0.15 |

Ease ограничивается снизу значением 1.3.

Затем интервал:

| Оценка | Новый интервал |
|---|---|
| `again` | → `relearning`, шаг 0, due = now + 600 с; `lapses += 1`; сохранённый интервал = max(1, старый × 0.5) |
| `hard` | старый × 1.2 |
| `good` | старый × ease |
| `easy` | старый × ease × 1.3 |

Итог ограничивается сверху 365 днями, снизу 1 днём, затем к нему применяется случайный разброс ±5% (чтобы карточки не слипались в один день).

**`relearning`:**

| Оценка | Результат |
|---|---|
| `again` | шаг 0, due = now + 600 с |
| `hard` / `good` | → `review` с интервалом, сохранённым при провале |
| `easy` | → `review`, интервал = сохранённый × 1.3 |

### 6.3. Маппинг автоматических режимов в оценку

Режимы с выбором варианта и вводом не показывают четыре кнопки. Их результат маппится так:

| Условие | Оценка |
|---|---|
| Ответ неверный | `again` |
| Верный, время ответа > 10 с | `hard` |
| Верный, время ответа 3–10 с | `good` |
| Верный, время ответа < 3 с | `easy` |

### 6.4. Формирование очереди на день

```swift
func buildQueue(limitNew: Int, limitReviews: Int, deck: DeckFilter) -> [Word]
```

1. **Повторения:** все карточки с `dueDate <= now`, `state != .new`, `isSuspended == false`, подходящие под фильтр колоды. Сортировка по `dueDate` возрастанию. Лимит `limitReviews` (по умолчанию 200).
2. **Новые:** карточки без `WordProgress` или в состоянии `.new`, подходящие под фильтр. Сортировка по `level`, затем по `id`. Лимит `limitNew` (по умолчанию 10, настраивается: 5 / 10 / 20 / 30 / без лимита).
3. Перемешать так, чтобы новые распределились равномерно между повторениями, а не шли блоком.
4. Карточки в состоянии `learning`/`relearning` с наступившим `dueDate` возвращаются в конец текущей сессии (внутрисессионное повторение).

## 7. Режимы тренировки

Все режимы работают с одной очередью (раздел 6.4) и по завершении карточки вызывают `SRSScheduler`. Режим задаётся настройкой сессии; по умолчанию — `flashcards`.

### 7.1. Flashcards (базовый)

Лицевая сторона: `czech` + картинка (если есть) + кнопка озвучки.
После тапа «Показать ответ» — перевод на выбранный язык, часть речи, род/вид (для мужского рода — с пометкой одушевлённости: «м. р. одуш.» / «м. р. неодуш.»), родительный падеж (для существительных), `note` (если есть), оба примера с переводами.
Внизу — четыре кнопки оценки с подписями интервалов: `Снова` / `Трудно` / `Хорошо` / `Легко`. Над каждой — рассчитанный интервал («10 мин», «1 д», «4 д»).

Направление показа настраивается: `CZ → перевод` (по умолчанию), `перевод → CZ`, или смешанное (случайно 50/50).

### 7.2. Multiple choice

Вопрос: `czech`. Четыре варианта перевода на выбранный язык (`primaryTranslation`). Один верный, три дистрактора.

**Правила генерации дистракторов** (в порядке приоритета, до набора трёх):

1. Если у слова `note` содержит подстроку «Ложный друг» — первым дистрактором взять слово, которое пользователь мог бы спутать: ищем в словаре запись, чей `russian` содержится в `note` целевого слова. Если не нашли — пропустить правило.
2. Слова из той же `category` и того же `level`.
3. Слова из той же `category` любого уровня.
4. Слова того же `level` из любой категории.

Ограничения: дистрактор не должен совпадать по `primaryTranslation` с правильным ответом или с уже выбранным дистрактором; дистрактор не должен быть фразой, если целевое слово — не фраза. Порядок вариантов перемешивается.

Обратный вариант (перевод в вопросе, чешские слова в вариантах) включается той же настройкой направления, что и во Flashcards.

### 7.3. Typing (письменный ввод)

Вопрос: перевод на выбранный язык + картинка. Пользователь вводит чешское слово.

**Проверка ответа:**

1. Обрезать пробелы, привести к lowercase.
2. Точное совпадение с `czech` → верно.
3. Совпадение после удаления диакритики (сравнение `searchKey`) → **верно, но с предупреждением**: показать правильное написание с подсвеченными диакритическими знаками и засчитать оценку не выше `hard`. Это осознанное решение: заставлять набирать `ř` и `ě` на системной клавиатуре — барьер, но игнорировать диакритику полностью нельзя.
4. Расстояние Левенштейна ≤ 1 при длине слова ≥ 5 → показать «почти верно», засчитать `hard`.
5. Иначе — неверно.

Под полем ввода — кнопка «Не знаю», эквивалент оценки `again`.

Для фраз режим недоступен (слишком длинный ввод) — фразы в этом режиме пропускаются.

### 7.4. Listening (аудирование)

Автоматически проигрывается `czech` через TTS. Пользователь выбирает правильный перевод из четырёх вариантов (дистракторы — по правилам 7.2) либо вводит услышанное (настройка).

Кнопка повторного проигрывания, а также проигрывания в замедленном темпе (`rate` × 0.6).

Режим недоступен, если системный чешский голос не установлен (см. раздел 9) — тогда он скрыт из выбора режимов.

### 7.5. Matching (игра на сопоставление)

Экран с 2 колонками по 5 элементов: слева чешские слова, справа переводы вперемешку. Пользователь тапает пару. Верная пара исчезает с анимацией, неверная — подсвечивается красным и разъединяется.

Таймер на скорость, результат не влияет на SRS напрямую, но каждая верно собранная пара засчитывается как `good`, неверная попытка по паре — как `hard` для соответствующего слова. Набор из 5 слов берётся из головы очереди.

### 7.6. Cloze (пропуск в предложении) — внутри Flashcards

Дополнительный формат обратной стороны, включается настройкой. Показывается `example_1_cs` с заменой целевого слова на `_____`, пользователь вспоминает и проверяет себя.

**Алгоритм поиска слова в примере:**

1. Взять первое слово из `czech`, нормализовать (без диакритики, lowercase).
2. Основа = первые `min(5, max(3, длина − 1))` символов.
3. Искать в нормализованном `example_1_cs` по границе слова (`\b` + основа).
4. Если не нашли — попробовать `example_2_cs`.
5. Если не нашли нигде — cloze для этого слова недоступен, показывается обычная обратная сторона.

Покрытие на текущих данных: **1676 из 1744 записей (96%)**. Реализовать юнит-тест, проверяющий, что покрытие не ниже 95%.

## 10. Картинки

- Источник: `image_url` (формат `https://loremflickr.com/640/480/<теги>`). Заполнен у 1005 записей.
- Загрузка: `URLSession` с настроенным `URLCache` (memory 50 МБ, disk 200 МБ) **плюс** собственный дисковый кэш в `Caches`, ключ — `id` слова. Причина: loremflickr на один и тот же URL возвращает разные изображения, а карточка должна показывать стабильную картинку, иначе слово не привязывается к образу.
- Логика: при первом показе слова картинка скачивается и сохраняется как `<id>.jpg`; при последующих показах берётся с диска.
- Префетч: при начале сессии в фоне подгружать картинки для первых 20 карточек очереди.
- Fallback: нет сети или загрузка не удалась → показывать плейсхолдер (SF Symbol по части речи) без ошибки. Отсутствие картинки не должно блокировать карточку.
- Таймаут запроса: 10 секунд. Повторных попыток не делать в рамках сессии.
- Ограничение: при включённом Low Data Mode картинки не загружать.

## 14. Порядок реализации

### Этап 2. Ядро SRS

`SRSScheduler`, `SRSState`, `QueueBuilder`.
**Готово, когда:** юнит-тесты покрывают все переходы из раздела 6.2, включая граничные (ease не опускается ниже 1.3, интервал не превышает 365 дней, fuzz не выводит за границы); `QueueBuilder` корректно соблюдает лимиты и фильтры.

### Этап 3. Flashcards

Экран сессии, режим Flashcards, кнопки оценки с интервалами, экран итогов.
**Готово, когда:** можно пройти полный цикл: старт сессии → 10 карточек → итоги; прогресс сохраняется и переживает перезапуск приложения.

### Этап 4. Каталог и детальная карточка

`CatalogView`, поиск, фильтры, `WordDetailView`.
**Готово, когда:** поиск находит `pozor` по запросам `pozor`, `POZOR`, `внимание`, `увага`; скролл полного списка плавный.

### Этап 5. Озвучка и картинки

`SpeechService`, `ImageCacheService`.
**Готово, когда:** слово озвучивается, картинка после первой загрузки стабильно одна и та же и доступна офлайн; отсутствие чешского голоса корректно обрабатывается.

### Этап 6. Остальные режимы

Multiple choice, Typing, Listening, Matching, cloze-формат.
**Готово, когда:** `DistractorGenerator` покрыт тестами (в том числе правило для ложных друзей), `AnswerValidator` корректно обрабатывает все пять случаев из 7.3.

### Этап 7. Прогресс и настройки

`StatsView` с графиком, экран настроек, применение всех настроек.
**Готово, когда:** изменение любой настройки немедленно влияет на следующую сессию; сброс прогресса действительно всё очищает.

### Этап 8. Полировка

Тёмная тема, Dynamic Type, VoiceOver, анимации переходов между карточками, пустые состояния, обработка ошибок.

## 16. Известные ограничения данных

Разработчику важно знать, чего в данных нет, чтобы не проектировать на это:

1. **Нет транскрипции и аудиофайлов.** Произношение только через системный TTS; качество звука `ř` посредственное.
2. **Нет полных парадигм склонения.** Есть только родительный падеж — он задаёт тип склонения, но автоматический вывод остальных падежей даст ошибки на исключениях. Грамматические упражнения по падежам в MVP не делаем.
3. **Нет данных о частотности.** Порядок подачи новых слов внутри уровня — по `id`, то есть по категориям. Это приемлемо, но не оптимально.
4. **Картинки нерелевантны для абстрактных понятий.** У 571 записи `image_url` пуст осознанно (предлоги, союзы, числительные, абстракции). Не пытаться достроить URL для них из `english`.
5. **Данные не вычитаны носителем.** Примеры предложений сгенерированы; перед релизом их стоит отдать на вычитку. Архитектурно это означает: переимпорт данных должен быть безопасен для прогресса (см. 5.2).
